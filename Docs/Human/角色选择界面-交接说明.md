# 角色选择界面 - 占位场景交接说明

按美术手绘草稿制作，三栏布局：左角色列表（6 个角色，可滚动）/ 中模型展示 / 右上双页签（详细信息 / 工具选择）+ 右下队友。

## 交接内容

- `character_select.tscn` —— 角色选择界面场景（Godot 4.6，1920×1080）
- `character_select.gd` —— 占位用页签切换脚本（约 20 行，可保留也可替换）
- `project.godot` —— 本地预览用的最小项目配置（合进主项目时不需要）
- `assets/ui/backgrounds/cave_bg_soft.jpg` —— 全屏背景图（虚化版；`cave_bg.jpg` 是原图）
- `assets/characters/portraits/char_01~06_*.jpg/png` —— 6 个角色的大头照（左侧列表用）
- `界面预览-详细信息.png` / `界面预览-工具选择.png` —— 两个页签的渲染截图

## 页签切换（已可用）

`character_select.gd` 里 `TabDetail.pressed` / `TabTools.pressed` 控制 `DetailPage` 与
`ToolsPage` 的 `visible`，并同步两个按钮的 `button_pressed`。
默认打开「详细信息」：把 `_ready()` 里的 `_show_tab(0)` 改成 `_show_tab(1)` 即可默认工具页。

## 全屏背景图

- 图源 `assets/ui/backgrounds/cave_bg_soft.jpg`（1920×1071），由原图 `cave_bg.jpg`
  用 PIL 轻微高斯虚化（radius=10）+ 亮度 0.92 + 饱和 0.88 生成，让背景退到 UI 后面；
- `BackgroundImage`：`TextureRect` + `expand_mode = IGNORE_SIZE` + `stretch_mode = KEEP_ASPECT_COVERED`，
  任何分辨率下都铺满、不拉伸变形（原图与 16:9 差一点，会裁掉约 9px 上下）；
- 其上叠两层：`Background`（`ColorRect`，`Color(0.03,0.04,0.06,0.3)` 统一压暗）+
  `Vignette`（`TextureRect` 用 `GradientTexture2D` 径向渐变，中心透明、四角 alpha 0.62）；
- 想换图：直接替换 `cave_bg_soft.jpg`（保持同名），或在 `BackgroundImage.texture` 指到新资源；
  觉得太暗/太亮，调 `Background.color.a`；想恢复纯色底就把 `BackgroundImage` 删掉。

## 左侧角色头像

- 6 张图在 `assets/characters/portraits/`，**左侧列表与详细信息页共用**，命名与模型一一对应：
  `char_01_cuntou`（寸头哥）/ `char_02_baimao`（白毛男）/ `char_03_fenmao`（粉毛女）/
  `char_04_lanmao`（蓝毛男，png）/ `char_05_huangmao`（黄毛女）/ `char_06_hemao`（黑毛男）；
- 每个 `Slot1~Slot6` 内部是 `Avatar`（TextureRect）：`expand_mode = IGNORE_SIZE` +
  `stretch_mode = KEEP_ASPECT_COVERED`，四边内缩 6px，这样选中时的琥珀描边不会被图盖住；
- 原图约 680×680（正方形），槽位 150×140，铺满会上下各裁一点（约 7%），不影响看脸；
  想完整显示就改成 `KEEP_ASPECT_CENTERED`（两侧会留黑边）；
- 换图只替换同名文件即可，场景不用动；新增角色则复制一个 Slot 并在脚本 `char_slots` 里登记；
- 详细信息页头像占位（原「头像」Label）已换成 `AvatarFrame/Avatar`（TextureRect，76×76，
  KEEP_ASPECT_COVERED），切换角色时由 `_apply_character()` 换贴图。

## 程序接入要点

**以下交互已在占位脚本 `character_select.gd` 里实现并可运行**（点着就能看效果），
接入时保留交互结构、把假数据换成真数据即可：

1. `BtnBack.pressed` → 返回准备间（占位脚本未接，程序自接）
2. 角色选择 `_select_character(i)`：
   - 框选描边跟随（StyleBox 覆盖切换）
   - `CharList.ensure_control_visible()` 选中项滚出可视区时自动滚回可见
   - `ArrowIndicator` 箭头由 `_process()` 每帧用全局坐标垂直居中跟随选中槽位（滚动/布局变化都会自动跟上）
   - 占位模型换色（`CHAR_COLORS`，正式接入后改为实例化对应角色场景）
   - `NameTag` 文字 = `CHAR_NAMES[i]`（现为真实角色名：寸头哥 / 白毛男 / 粉毛女 / 蓝毛男 / 黄毛女 / 黑毛男）
   - 详细信息页 `AvatarFrame/Avatar` 贴图与 `NameLabel` 文字同步切换（`CHAR_PORTRAITS[i]`）
3. 工具选择 `_select_tool(i)`：框选跟随 + `ToolInfo` 文字/攻击力/耐久度联动，
   数据源 `TOOL_DATA`（name/type/desc/atk/dur），进度条 max_value=100
4. `BtnConfirm.pressed` → `_toggle_confirm()`：按钮文字「确认/取消确认」切换，
   并同步 `TeamSlots/P1/Status` 为「已确认」（绿）/「选择中…」（灰）
5. 页签切换 `_show_tab(0/1)`：默认详细信息，改 `_ready()` 里参数可换默认页
6. 工具数量多了直接复制 `Tool6`（网格自动换行，滚动条自动出现），并把新按钮加进 `tool_slots`
7. 3D 展示：替换 `CharacterPlaceholder` 下节点为正式模型，相机/灯光/地台已就位；旋转建议对该节点 `rotate_y`
   - 展示区背景是**透明**的（`SubViewport.transparent_bg = true` + `Environment.background_mode = 0`
     跟随清屏色），角色直接叠在全屏背景图上；
   - 想恢复成纯色底：把 `transparent_bg` 关掉、`background_mode` 改回 1（BG_COLOR）
     并设 `background_color`；
8. 所有文案都是 Label.text，改字不动结构；页签按钮是 toggle Button，也可换成 TabContainer

```ini

```

- `Background` 是全屏纯黑 ColorRect（anchors 全屏、mouse_filter=Ignore），
  位于节点列表最底层，`expand` 撑出的额外区域由它铺底，不会露出游戏场景；

## 角色模型（voxel → glTF）

美术用 MagicaVoxel 编辑的 `.vox`，经 `tools/vox2glb.py` 转为 `.glb`，放在 `assets/characters/`：

| 槽位 | 文件 | 三角面 |
|---|---|---|
| 1 | `char_01_cuntou.glb` | 5.2 万 |
| 2 | `char_02_baimao.glb` | 8.7 万 |
| 3 | `char_03_fenmao.glb` | 9.0 万 |
| 4 | `char_04_lanmao.glb` | 8.4 万 |
| 5 | `char_05_huangmao.glb` | 8.4 万 |
| 6 | `char_06_hemao.glb` | 9.7 万 |

模型规格（脚本会自动再摆一次，不依赖导出设置）：

- **Y 轴向上**，脚底在 `y = 0`，XZ 原点居中，统一高度 **2.2** 单位；
- 颜色烘焙在**顶点色**（`COLOR_0`，线性空间），没有贴图文件，材质由 Godot 导入时自动生成；
- 每个面都带**朝外的显式法线**（`NORMAL`，逐面法线 = 硬边体素质感）。早期版本不写法线，Godot 只能按屏幕导数推算，旋转模型时明暗会乱跳（表现为“光从角色背侧打过来”）；
- 每个模型 2~4 MB。原始 Meshy 高模（32~50MB / 57~120 万面）已备份到仓库外，未提交。

切换逻辑在 `character_select.gd`：

- `CHAR_MODELS` 数组按槽位顺序列模型路径，换模型只改这里；
- `_apply_model(i)` 释放旧实例 → 实例化新模型 → 用 `_subtree_aabb()` 算包围盒，自动 XZ 居中、脚底贴地台顶面；
- **转台展示**：模型只绕**竖直轴（Y）**自转，脚底永远踩在地台上；`MODEL_YAW`（默认 `PI`）是模型资源自带朝向的修正量，换模型若发现「背对镜头」，改这一个常量即可；
- 拖拽：`ModelPreview.gui_input` → `_on_preview_gui_input()`，左右拖 → 模型原地转台旋转（`ROT_SENS`）；**相机与地台固定不动**，画面里地台不会移动；
- `MODEL_SCALE`（默认 `1.35`）等比放大模型：头顶到预览框上沿留 ~32px；改这个值即可改角色在框里的大小（只影响角色，地台不动）；
- 整体高度：`CharacterPlaceholder` 节点的 `position.y`（当前 `-0.137`）决定“角色+地台”在画面里的高度，地台前缘距预览框底约 13px；想让整套上下挪，只改这一个值；
- 相机：`CAM_POS` / `CAM_LOOK_AT` 常量，`_setup_camera()` 在 `_ready()` 里摆一次，之后不再移动；
- 灯光：`DirectionalLight3D`（主光 1.0）与 `FillLight`（补光 0.45）都**挂在 `Camera3D` 下**，方向随镜头走 —— 光永远从镜头方向照向角色，转动角色时受光面始终朝向观众；
- 切角色时视角自动复位到正面。

### 地台（体素模型）

- 原来是一个 `CylinderMesh` 圆柱占位，现已换成美术提供的 `assets/props/pedestal.glb`
  （体素小场景：石台 + 草 + 矿石 + 提灯，原始尺寸 1.9 × 0.8 × 1.9 米）；
- 节点是 glb 的**实例**：`ModelPreview/SubViewport/CharacterPlaceholder/Pedestal`，
  位置 `(0, -0.91, -3.4)`；
- 为什么是 `-0.91`：模型包围盒顶面（0.355）不是地面，最高点是提灯。实测**朝上的大平面
  在本地 `y = -0.03`**（面积 2.19 的那层才是地面），所以要 `-0.94 - (-0.03) = -0.91` 才能让
  角色脚底正好贴合台面。换地台模型时，先量一下"面积最大的朝上平面"的高度再算；
- 地台**固定不动**：不参与旋转、不跟随角色，只随 `CharacterPlaceholder.position.y` 整体上下移。

### 队友头像

- 右下 4 个方框里各有一个 `Avatar`（TextureRect，填满 168×168 框，`KEEP_ASPECT_COVERED`）；
- **1P（主控）跟着当前选择变**：`_apply_character()` 里 `team_avatars[0].texture = load(CHAR_PORTRAITS[index])`，
  和左侧列表、详细信息页共用同一套 `CHAR_PORTRAITS`；
- 2P / 3P / 4P 目前是固定占位（白毛男 / 粉毛女 / 黄毛女），正式联机时由各玩家上传的选择数据替换
  `team_avatars[1..3].texture` 即可；
- 头像下方 `Status`（选择中…/已确认）仍由各自的游戏状态驱动，1P 的跟「确认」按钮联动。

### 待机呼吸（顶点着色器，无需骨骼）

模型是单块网格、没有骨骼和可拆部件，所以呼吸用**顶点着色器**做，不改美术文件：
`scenes/ui/shaders/voxel_breathing.gdshader`

- `character_select.gd::_apply_breathing()` 在换模型时新建一个 `ShaderMaterial`（`material_override`），并把模型包围盒的 `base_y` / `model_height` / `model_width` 写进 uniform —— 换任何同规格模型都能直接用，不用改参数；
- `_process()` 每帧把 `sin(时间 × TAU / BREATH_PERIOD)` 写给 `breath`（-1~1），`BREATH_PERIOD` 默认 `3.6` 秒；
- 效果由两部分叠加：
  - **身体上下**：`lift_start`（0.02）以下位移为 0，往上 `smoothstep` 升到满幅 `amp_lift`，所以脚掌不动、上身整体起落；
  - **胸腔扩张**：上下各有一道门（`chest_lo` 0.45 → `chest_hi` 0.62 渐入，`chest_fade_from` 0.74 → `chest_fade_to` 0.80 渐出），只在胸口一段做径向膨胀；**肩线以上权重为 0，头和帽子尺寸完全不变**；再用 `torso_edge_lo/hi`（0.80 / 1.05，占半身宽比例）做横向衰减，避免把手往外推；
- 实测（呼气 ↔ 吸气，模型高约 580px）：头顶上下 **5px**、胸口宽 **+7px（约 3%）**、帽宽 241→240px（不变）、腰以下与地台**像素差恒为 0**；
- 可调参数（shader 里改默认值即可）：`amp_lift` 0.010（起落）、`amp_chest` 0.020（扩张）、`amp_sway` 0.003（侧摆）；想要更明显就同步加这两个，别只加扩张——只扩张会像“充气”；
- **注意**：`pow()` 在底数为负时是未定义行为，会返回 NaN 把顶点坐标污染成无效值（表现为模型只剩半个头）。高斯包络必须写成 `u * u`，不要写 `pow(u, 2.0)`。

游戏里复用时，对任意 `MeshInstance3D` 设同一个 `material_override` 并每帧写 `breath` 即可；想给不同角色不同节奏，就每个实例各建一个 `ShaderMaterial` 改 `BREATH_PERIOD` 对应的相位。

这是"只有上半身会动"的方案，走路/挥镐这类需要关节的动作做不到 —— 那时要按 `vox2glb` 拆件做刚体动画，或在 Blender 里绑骨（见下方"待确认"）。

**重新导出模型**：`python tools/vox2glb.py <输入.vox> <输出.glb> 2.2`
（脚本做法：解析 VOX → 提取外露面 → 同色贪心合并成矩形 → 顶点色 → Z-up 转 Y-up）
注意：面片绕序由叉积计算后与目标法线比对决定，保证全部朝外；早期版本硬编码绕序导致前后两面朝内，被 Godot 背面剔除后会看到「像素一块块消失」。
导出用自己写的 `write_glb()`（POSITION / NORMAL / COLOR_0 + 索引），不再依赖 trimesh 的 glTF 导出，确保法线一定写进文件。
另：**改动 .glb 后必须用编辑器跑一次导入**（或删除 `.godot/imported/` 下对应缓存），否则直接运行游戏仍会加载旧网格。
