# 《胡闹矿洞》关卡部分模块化改造建议

> **进度更新**：本文第 6 节的第 1～4 步已经落地代码（`modules/level/`、`scenes/levels/level_sandbox.tscn`）。
> 现在的接口与迁移方式以 [`关卡接口契约.md`](关卡接口契约.md) 为准，未实现项见
> [`关卡缺口清单.md`](关卡缺口清单.md)。本文保留作为决策依据与设计理由。

> 针对工程 `VoxelGame`（Godot 4.6.2，主场景 `scenes/levels/mine_playground.tscn`），
> 对照《功能模块总述大纲》与 L01～L07 需求案的现状体检与落地路径。

## 0. 结论先说

**能模块化，而且现在是成本最低的时机。**

当前关卡相关代码只有 5 个脚本、约 620 行，L02/L03/L05/L06/L07 都还没落地。等这些系统长出来再拆，
就要连场景、存档、UI 一起改。现在拆只动脚本边界，不动玩法。

真正需要改的不是"架构"，而是三件事：

1. **掉落与方块数据写死在代码里** → 需求案是 18 件物品 × 7 层权重表，必须数据化。
2. **网格数据、渲染、交互、表现挤在一个类里** → `voxel_world.gd` 同时干 4 件事。
3. **模块之间靠具体节点互摸** → `mine_cart.gd` 直接调 `_world.is_blocked_at()`，没有"轨道/稳定度"的位置。

## 1. 现状体检

### 1.1 代码清单

| 文件 | 行数 | 现在干什么 | 对应需求 |
| --- | ---: | --- | --- |
| `scripts/world/voxel_world.gd` | 315 | 生成矿道 + `grid` 数据 + MultiMesh 渲染 + DDA 拾取 + 剖面隐藏 + 掉落抽取 | L01（全部）+ 一点 L02 |
| `scripts/systems/mining_controller.gd` | 227 | 鼠标射线 → 悬停描边 → 蓄力 → 破坏 → 粒子 → 刷新 HUD | P03/P04 + U03 + 表现 |
| `scripts/world/mine_cart.gd` | 44 | 平台自动前进、撞到方块停 | L04（1/3） |
| `scripts/player/player.gd` | 66 | 移动、跳跃、平台夹取 | P01（1/3） |
| `scripts/ui/mining_hud.gd` | 27 | 显示"已挖 N / 分项" | U01（很小一块） |

`scenes/levels/mine_demo.tscn` 是纯美术场景（57 个节点、无脚本、无 ext_resource），画了轨道、支撑柱、
矿车外形——**建议直接当 L03/L04 的视觉验收基准**，别删。

### 1.2 四处硬耦合（必须拆的）

**① 数据与表现混在 `voxel_world.gd`**

```gdscript
# voxel_world.gd:81-91  掉率写死在代码里
func _pick(ore_chance: float) -> String:
    if _rng.randf() < ore_chance:
        if r < 0.55: return "gold"      # 5 种方块
        elif r < 0.85: return "quartz"
```

而 L01 要的是：18 件物品、三类别、每层 100,000 权重、高价档随深度增长、西瓜皮补差。
现在这套 `_pick` 既不能表达"个位数的千分比"，也不能表达"按深度换表"，更不能让策划改数值。
**这是当前最大的返工风险。**

**② 一个类干四件事**

`voxel_world.gd` 里 `grid`（数据）、`_build_visuals`（渲染）、`raycast_block`（查询）、
`update_cutaway`（剖面）、`break_block`（结算）互相调用。想单独测"挖穿后掉落是否正确"，
必须先把整个 MultiMesh 建起来。

**③ 交互层直接抓着世界和 HUD**

`mining_controller.gd:105` 直接 `_world.break_block(pos)`；`:_130` 用
`_hud.has_method("update_counts")` 鸭子类型推 HUD。P04 在需求案里只要提交"覆盖格 + 破岩词条"，
这里却把射线、蓄力、粒子、UI 全绑在一起。

**④ 矿车直接摸世界，没有轨道概念**

```gdscript
# mine_cart.gd:31  只有一个"有没有方块"的判断
blocked = _world.is_blocked_at(next, deck_half_width, deck_half_depth, ...)
```

L04 要求停车原因分四种（未清岩 / 轨道未就绪 / 落石 / 下潜过渡），现在只有第一种；
`update_cutaway`（纯表现）也由矿车直接驱动。等 L03 进来，矿车要改的地方会牵连世界脚本。

### 1.3 现状 vs 需求案的缺口

| 需求 | 现状 | 差什么 |
| --- | --- | --- |
| L01 18 件掉落 × 各层权重 | 5 种方块，硬编码 | 物品表、权重表、深度表（数据化） |
| L01 挖掘进度 / 裂纹 / 多人共挖 | 一次性 0.4 秒挖穿 | 每格 `progress`、阈值、开裂表现 |
| L02 每层 50×d 格、累计下潜点 | 无 | `LevelState`（深度、推进、下潜事件） |
| L03 轨道、支撑、稳定度、坍塌 | 只有美术版 `mine_demo` | `TrackService` / `StabilityService` |
| L04 矿车 6×9 格、停车原因、车尾回收 | 2.8×3.6、单一停止条件 | 车体数据 + 查询接口 |
| L05 丧尸两路刷怪 | 无 | `MonsterSpawner` |
| L06 熔炉商人经济 | 无 | `EconomyService` |
| L07 16 项随机事件 | 无 | `EventRouter`（订阅事件总线） |

## 2. 目标结构

```
res://
├─ game/                      # 跨模块的地基件
│  ├─ events/game_events.gd   # 事件总线（autoload）
│  └─ data/                   # 全局数据资源
├─ modules/
│  ├─ level/                  # ← 你负责的这块
│  │  ├─ core/level_state.gd          # L02 深度 / 推进 / 下潜
│  │  ├─ grid/voxel_grid.gd           # L01 纯数据：格子、进度、破岩
│  │  ├─ grid/voxel_renderer.gd       # L01 表现：MultiMesh、裂纹、剖面
│  │  ├─ loot/loot_table.gd           # 数据资源
│  │  ├─ loot/loot_service.gd         # L01 抽掉落
│  │  ├─ rooms/room_planner.gd        # L02 房间预留与显现
│  │  ├─ track/track_service.gd       # L03 轨道生成 / 回收
│  │  ├─ track/stability_service.gd   # L03 稳定度 / 坍塌
│  │  ├─ cart/cart_controller.gd      # L04 行进 / 停车原因
│  │  ├─ monsters/spawner.gd          # L05
│  │  ├─ economy/economy_service.gd   # L06
│  │  └─ events/event_router.gd       # L07
│  ├─ player/                 # P 模块（别写进 level）
│  └─ ui/                     # U 模块
└─ scenes/
```

关键点：**每个模块 = 一个脚本 + 一个可选测试场景**，谁负责谁开目录，互不越界改文件。

## 3. 模块契约

| 模块 | 对外提供 | 依赖谁 | 依赖方式 |
| --- | --- | --- | --- |
| L01 `VoxelGrid` | `apply_mining(cells, power, miner)`、`has_block`、`is_blocked_at`、`raycast_block` | 只依赖 LootService | 直接调用（纯逻辑，无节点） |
| L01 `VoxelRenderer` | 订阅 `block_changed` 刷新实例 | 只依赖 VoxelGrid | **只读订阅** |
| L02 `LevelState` | `depth`、`progress`、`depth_at_cell()`、`advance()`；信号 `depth_changed` / `descend_started` | 无 | 被大家只读 |
| L03 `TrackService` | `on_route_cleared(cell)`、`is_track_ready(box)`、`is_reclaimable(cell)` | L01 通知、L02 深度 | 事件订阅 |
| L03 `StabilityService` | `stability_of(segment)`、`place_pillar()`；信号 `segment_critical` / `collapse` | L01、L02、L05 活怪数 | 查询 + 订阅 |
| L04 `CartController` | 位置、停车原因枚举；信号 `cart_blocked(reason)` | L01、L03（**只查接口**） | 只读查询 |
| L05 `Spawner` | 刷怪、击杀通知 | L02 推进、L01 出生位 | 事件订阅 |
| L06 `EconomyService` | `sell(items)`、`buy(...)`、共享金币；信号 `coins_changed` | L01 物品表 | 直接调用 |
| L07 `EventRouter` | 16 项事件判定 | 订阅全局事件 | 事件订阅 |

**约定：跨模块只允许两种通道——① 明确的函数调用（同步查询）；② 事件总线的信号（异步通知）。
禁止 `get_node("../OtherModule")` 摸别人的内部状态。**

## 5. 数据资源设计（这件事最急）

```gdscript
# loot_table.gd  —— 100,000 整数权重，按层取
class_name LootTable extends Resource
@export var item_id: String
@export var price: int
@export var tier: int              # 0 垃圾 / 1 矿物 / 2 古董
@export var weights: PackedInt32Array   # 下标 = 深度-1
```

对应 L01 的表：

| 深度 | 高价档总权重 | 永乐大典 | 比特币硬盘 | 清明上河图 | 西瓜皮 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 600 | 300 | 210 | 90 | 15,400 |
| 2 | 700 | 350 | 245 | 105 | 15,300 |

其余物品固定权重，`weights` 数组里逐层复制即可。抽一次用 `randi() % 100000` 落在哪个区间就出哪件，
多格挥击逐格独立抽。这样策划改表 = 改 `.tres`，不动代码。

同理需要三个数据资源：`block_type.tres`（key、硬度、材质、掉落表引用）、`depth_config.tres`（层长、
下潜点、高价档概率、柱覆盖边长、稳定度衰减）、`room_def.tres`（房型、尺寸 9×12、矿种、权重）。

## 6. 迁移顺序

每步都能单独跑、单独验收，不要一次改完：

| 步骤 | 做什么 | 验收 |
| --- | --- | --- |
| 1 | 抽出 `.tres` 数据（方块/掉落/深度），`_pick` 改成查表 | 挖 1000 格统计各类比例，对上表 1 层数值 |
| 2 | 拆 `voxel_world.gd` → `VoxelGrid`（纯数据）+ `VoxelRenderer`（只订阅） | 挖矿行为不变；无渲染也能跑网格单测 |
| 3 | 加 `GameEvents` 总线，HUD/粒子改订阅，删掉 `has_method` 鸭子类型 | 挖矿时 HUD 仍更新；换 HUD 不影响挖掘 |
| 4 | 加 `LevelState`，矿车改"只查接口"并输出 `StopReason` | 矿车能报告"因为轨道没铺"而停 |
| 5 | 之后 L03/L05/L06/L07 各开目录，L01 核心不再改动 | 新模块加进来不碰 `voxel_grid.gd` |

第 1、2 步做完，别人就能在不动你的情况下接 L03/L05；这是并行开发的分水岭。

## 7. 分工协作约定

- **目录即边界**：`modules/level/*` 你改，`modules/player/*` 别人改。跨目录只提 PR 说明接口变更。
- **信号命名**：`过去式 + 主体`（`block_broken`、`depth_changed`、`segment_collapsed`），参数只传基础类型和 Vector3i，别传节点内部状态。
- **每个模块配一个 `test_*.tscn`**：L01 的掉落测试场景不加载玩家和 UI，直接 `VoxelGrid` + 断言。
- **接口先冻结再并行**：先和 P03/P04、L03、L04 的负责人对齐 `apply_mining()` 和 `StopReason`，再各自开工。
- **数值全进 `.tres`**：代码里不留 `0.55`、`0.4`、`2.2` 这类魔法数。

## 8. 风险与不要做的事

- **别上 ECS**。7 个模块、单机玩法，节点 + 信号足够；ECS 会让策划和美术都进不来。
- **别在 L01 上塞 L03 的逻辑**。轨道、稳定度有自己的计时和结算段，塞进网格会变成第二个巨石类。
- **别急着做存档**。等 `LevelState` + `EconomyService` 稳定后再序列化，否则存档格式要返工。
- **`mine_demo.tscn` 保留**：它是 L03/L04 的美术基准，也是视觉回归的参照。

## 9. 现状 → 目标的本周可做清单

1. 写 `block_type.tres` / `loot_table.tres` / `depth_config.tres` 三份数据，填第 1～2 层。
2. `_pick()` 换查表，加 `apply_mining()` 签名（先保留一次性挖穿，后面再加进度）。
3. 拆 `VoxelGrid` / `VoxelRenderer`，先把 `update_cutaway` 挪到渲染层。
4. 加 `GameEvents` autoload，HUD 改订阅。

做完这四条，L01 的地基就稳了，L03/L05 的负责人可以开始接。
